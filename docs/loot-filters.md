# Loot filters

The simulator's **Covens & Threads** scene provides varied 3.30 league-item examples, including Threads, Enshrouded items and Viscera. The examples test filter behavior; they are not a prediction of encounter drops.

**Preset highlights** samples exact currency names from high-emphasis blocks in the pinned NeverSink Regular preset when their item class is known. It is a snapshot of that preset's styling, not a list of live prices, trade recommendations or drop rates. Your active filter still determines each preview result.

Generated unidentified magic and rare examples have an unknown item tier unless a rule or sample explicitly supplies one. A tier-dependent filter therefore reports an unknown result until the tier is set. **Tiered gear** compares explicit example tiers; in Ruthless it shows only the example without a tier because items there do not have tiers.

**Map tiers** compares synthetic map examples from tier 1 through tier 17, with an Abomination Map for the Nightmare example. The tiers are explicit sample properties for testing filter rules, not estimates of drop rates or map availability. The same scene is available through MCP `test_loot_filter_scene`.

Open **AI builds**, **Atlas**, or **Crafting**, then choose **Loot filter**. **Alt+5** opens it from any planning page.

The workspace has six pages:

- **Overview:** choose a profile and strictness, auto-adjust from the build, and preview a collection of drops.
- **Customize:** browse personal pickups or the complete base preset by category. Search for an item, then edit its colours, size, sound and icon. Editing a base rule creates a personal override. **Advanced conditions** opens its matching criteria, including every condition supported by the simulator.
- **Tiers:** copy a preset tier or create your own, then drag exact item names between custom tiers. Move tiers up/down to change priority. Existing class and stack conditions stay attached; incompatible exact classes cannot be mixed by dragging. Delete an override to return to the base preset. Select **Stack styles** on a custom tier to give stacks above chosen sizes another custom tier's visibility and appearance; the dialog previews the selected style and profile-wide appearance on an item label. Higher-priority rules can still change the result. Larger thresholds take priority; the source tier's conditions and Continue behavior still apply. Personal pickup rules come first. These settings are manual and do not use live prices.
- **Simulate:** generate example loot, select drops to inspect their results, configure an item, and show or hide hidden drops. Use Previous / Next to browse every example; hidden-drop filtering happens before paging. These are deterministic examples, not a model of drop rates.
- **Style:** choose generated-target palettes or restyle personal pickups. **Whole-filter appearance** controls declared font sizes, colour overrides, alerts, minimap visibility and beams across the compiled filter. Blank colours preserve tier palettes. Undeclared styles retain `Continue` inheritance; **Restore original** removes these settings. External `Import` contents remain unresolved.
- **Modules:** create a named snapshot of personal rules and tiers, copy it between profiles, or copy/paste a shared module. **Update copies in this build** explicitly refreshes matching snapshots. Modules follow personal rules and custom tiers in priority.

**Profile tools** includes profile management, **Review changes** and **Linked build targets**. Review compares the draft with kept profiles; Undo/Redo restores edits. Linked targets flag changed sources and open their craft, gear, resource or Atlas plan. When several sources need the same pickup, each keeps its own link; repeated needs within one source share a rule. **Tools → Recover local drafts** restores interrupted edits without applying them. Keep profiles before using normal **Save**.

**Campaign and base-family pickups** in Profile tools selects weapon/offhand families, armour defence combinations and recipe pickups. **Use equipped** selects families from active gear and the active weapon set, preserving recipe pickups. The area range limits these supplemental Show rules; the upgrade window raises the minimum base DropLevel in five-area bands. Set the window to 0 to retain every selected base. Recipe pickups use only the area range. Socket recipes include all item rarities and follow vendor priority: six links, six sockets, then linked colours. Recipe pickups take priority over selected base families. Personal rules, custom tiers and modules keep priority. Customize → Policies previews the resulting blocks; no unrelated items are automatically hidden.

The optional **Low-level unidentified rare set pieces** policy marks items below level 60 in purple for the Alchemy Orb set recipe. A complete set still needs every slot; higher-level pieces can fill other slots. The optional **Unidentified rare set pieces** policy shows unidentified rare equipment with item level 60 or higher. Gold borders mark levels 60–74; blue marks 75 and above. Use the slots control to highlight only jewellery, armour, or weapons and shields you are collecting; the saved policy and AI tools retain this selection. For the normal-mode Chaos Orb set recipe, all pieces must be level 60 or higher and at least one must be 60–74; a full set of level 75+ pieces yields Regal Orbs. See the [rare-set recipe](https://www.poewiki.net/wiki/Vendor_recipe_system#Full_Rare_Sets) and [3.30 patch notes](https://www.pathofexile.com/forum/view-thread/4013680). The filter cannot track a completed set, vendor eligibility, or currency proceeds, and higher-priority rules or appearance settings can change the result. These rare-set policies are not emitted in Ruthless while availability there is unverified.

**Saved example sets** keeps exact test items with the profile. On Simulate, choose **Saved sets**, name the set, then capture the current item, tested history or current scene. **Use selected** displays that set; its original item and area levels are preserved. A configured or pasted item appears as a separate current test beside the set; it does not overwrite the saved examples. Item levels and hover details distinguish examples sharing a base. Rename, replace and removal are staged until accepted. Keep in build and Save to share or reopen these tests. Missing properties remain unknown. The **Maps & threads**, **Flasks & tinctures**, **Divination cards** and **Essences** scenes provide named examples for testing those rules; their contents and order are not estimates of actual drops or value. Current tier-based map examples include their explicit tiers; the examples do not establish map availability or drop rates.

**Crafting materials** provides fossils, resonators, Eldritch currency and Lifeforce examples. **Heist & Expedition** includes contracts, blueprints, a logbook and vendor currencies. These are fixed examples, not predicted loot or prices. Resonator sockets remain unknown until configured.

For influence tests, `HasInfluence Shaper Elder` matches either influence, while `HasInfluence == Shaper Elder` requires both, as in [GGG's filter examples](https://www.pathofexile.com/forum/view-thread/2687401). Exact matching with additional influences remains an uncertain preview until verified.

When matching rules use `Continue`, a later numbered alert replaces the earlier numbered alert, including `None` to disable it. Custom sounds retain their separate precedence. If a single block specifies both numbered alert modes, the reference-sound preview reports that the effective sound is unverified.

**Category appearance**, on Style or in Profile tools, changes declared colours, fonts, alerts and effects for one item family. Rules stay at their original priority. Whole-filter appearance applies last. The picker shows active block counts; categories follow preset labels and rule conditions, so check Customize when styling an imported rule. Restore original removes the category's settings.

Choose **Pick** beside a colour field to open the colour wheel. Drag the wheel, brightness or opacity bars, choose a quick colour, or enter exact hex/RGBA values. Arrow keys adjust a focused selector. **Keep colour** returns to the editor; **Cancel** leaves it unchanged. When an imported background colour omits opacity, the preview and picker use the game's default of 240. Ruthless text colours require alpha 80 or higher.

**Saved palettes**, on Style or in Profile tools, stores the current whole-filter appearance, category styles and generated-target theme. Name a snapshot, then use it on the profile later. Editing the active appearance does not overwrite the saved snapshot. Palette changes preserve pickup conditions. Libraries travel in native builds and planning bundles and have no collection-count cap within the shared metadata size guard.

**Filter structure and priority** shows every active compiled block under collapsible source sections and item families. Search exact source text or filter to hidden, Continue, conflict or warning blocks. Select a block to inspect its line, diagnostics and full text, copy it, or edit it. Non-personal blocks create stable personal overrides; reopening them from matched-rule inspection uses the same identity. Priority conflicts include provably unreachable blocks with rarity tier comparisons, including exclusions, and narrower numeric thresholds. The analysis is bounded and can miss conflicts. Disabled personal rules stay in Customize. Unresolved external imports remain explicit.

Create campaign, early mapping and endgame profiles for Normal or Ruthless. In Ruthless mode, Hide blocks become Minimal blocks, matching the game format. Choose a NeverSink strictness and a style for newly generated rules. **Auto-adjust for this build** adds pickup rules from saved crafting starting items and recognized modeled recipe currencies, planned gear bases, active gems and links, recognised budget resources and saved Atlas strategies. Support-gem pickups use their in-game names. Campaign skill-group pickups use the number of linked sockets, including white sockets; matching gem colours can still improve quality. Recipe service costs and unknown ingredients are not guessed as drops. Generation replaces its previous generated rules while keeping personal rules. These are snapshots: regenerate after changing your build or plans. Gear-base rules do not identify hidden modifiers or distinguish unique variants sharing a base.

For planned Viscera, generated pickups match the underlying base name and Viscera class. They do not distinguish Lesser or Greater variants or their modifiers; inspect the item before using it.

For budget pickups, use an exact currency name such as `Pristine Fossil` or `Greater Eldritch Ichor`; simple plurals are recognised. The bundled crafting-item catalogue supplies the names, including fossils, catalysts, resonators and Eldritch currencies. Service descriptions and unrecognised budget labels do not become item rules.

Ordinary map items no longer identify a particular Atlas layout: since [3.28](https://www.pathofexile.com/forum/view-thread/3913392), a tiered Map item can open an eligible area chosen on the Atlas. Layout names such as `Beach Map` in strategy text, Shaped Regions or budget resources therefore do not create exact-base pickups. To highlight a particular ordinary map tier, use **Add map tier** in the Atlas strategy or enter an item such as `Map (Tier 16)` in its maps or supplies field; this highlights that tier regardless of the area you later choose. Recognized special map items such as Nightmare Maps and Vaal Temple Map still generate exact-base pickups. The **avoid** field suppresses matching generated items and Threads. A separate budget can still request the same item. The generator does not interpret negation in free text or establish item availability.

If a nonempty maps, supplies or avoid field contains no recognised item name, the build-pickup review points it out. Strategy notes can still be kept as free text; this check does not identify every unmatched phrase in a field that also contains a recognised item.

Named supplies also include the reviewed 3.30 Allflame Embers, Astrolabes, Maven's Chisels, Delirium Orbs, Divine Vessel, Royal Visage and the three Memory items that start Atlas traces. Recognised former names in saved strategies and **avoid** resolve to the current item name. Removed names without a replacement are excluded. The name catalogue is rebuilt with `python tools/update_atlas_filter_supplies.py path/to/base_items.min.json`; the pinned client hash and reviewed removal list are recorded with it.

Configured Awakener and recombination donors also add base pickups, using the donor's base type and minimum item level when provided. These broad rules do not identify the donor's required modifiers, influence or rolls; inspect an item before using it. If a configured donor cannot be read, its previous generated donor pickups are kept and the guide is flagged for review.

If a saved recipe cannot be inspected, or an action has no item ingredient breakdown, its previous generated recipe pickups are kept and the affected guide is listed for review. Known ingredients are still added. MCP generation returns the same warnings.

Linked-target checks, auto-adjust, and the first crafting-data decode run between frames. The auto-adjust button shows when work is in progress. If the build or filter changes during an update, try again. Loading the data file and inspecting individual recipes can still cause a pause.

The simulator's **Build targets** scene also prepares examples between frames. It shows a checking message until they are ready and refreshes them when the build changes. If a crafting guide cannot be fully inspected, the scene asks for review; the linked-target view explains the issue.

Select a rule to preview example properties. Examples are synthetic; modifier names come from the rule and do not establish that a real item with that combination can drop. **Edit** opens its live appearance controls; **Advanced conditions** opens matching criteria. All conditions must match. Move rules up or down to change priority; the first matching rule decides unless it uses `Continue`. **Silent** adds explicit alert-disable actions so a continued earlier rule does not supply an alert. The item's separate ground-drop sound is unchanged. Editing a generated rule turns it into a personal rule so regeneration preserves the edit. Disable a rule to try the filter without deleting it.

The drop preview shows the label, border and beam, and explains the deciding rule and line. Example currency and other known non-equipment use a defence percentile of zero; fixed-defence equipment uses 100. Random defence rolls and unrecognized cases remain unknown until you enter a percentile in **Configure an item**. **Test sample properties** or **Configure an item** lets you test exact item properties, including **MemoryStrands**, **Fated**, **TwiceCorrupted** and **UnidentifiedItemTier**. Memory strands stay unknown in examples unless supplied; pasting an item retains an explicit Memory Strands line. Use **More properties** to configure less common conditions, including base defences, enchantments and transfigured gems; use the page arrows on smaller windows. Leave unavailable fields blank, or choose **Unknown** for yes/no properties. For influence, enter **None** only when the item is known to be uninfluenced; a blank stays unknown. Shaper and Elder flags follow a known influence list; contradictory properties produce an uncertain preview. Explicit-modifier matching requires an identified sample and known modifier names. Missing properties, unsupported conditions or unresolved `Import` files produce **unknown** when they could affect the result. When an editable property is missing, **Configure** opens that field, including its page under **More properties**. GGG marks `AlwaysShow`, `HasVaalUniqueMod`, `IsVaalUnique` and `WaystoneTier` as PoE 2-only conditions in its [item-filter reference](https://www.pathofexile.com/item-filter/about). Existing imported or saved text is preserved, but filters containing those conditions cannot be exported for PoE 1 until they are removed. This simulator does not replace validation by the game. Numbered sound previews use original reference tones on Windows; the game's exact alert sounds play in game. Imported custom sound references are preserved, but their audio files are not bundled.

Socket previews distinguish the default match from exact matching: `SocketGroup RRR` also accepts extra linked sockets, while `SocketGroup == RRR` requires exactly three red sockets. A stated total such as `SocketGroup == 5RRR` permits two non-red sockets in the five-link. See [GGG's socket-filter examples](https://www.pathofexile.com/forum/view-thread/2771031) and [developer clarification](https://www.reddit.com/r/pathofexile/comments/f2t4tz/inconsistencies_in_new_filter_syntaxes/).

For socket conditions, enter linked groups separately in **SocketGroup** and all socket colours in **SocketColours**. When all colours are supplied, the simulator can count them without a separate **Sockets** value; colours alone do not establish links. If **Sockets** is known, the groups must account for every socket; otherwise group and derived link results are unknown. Enter `0` in **SocketGroup** or **Sockets** when the item has no sockets; leave the fields blank when unknown. Use R, G, B, W, A and D for red, green, blue, white, Abyss and Delve sockets; linked colours can be separated by hyphens. A rule such as `SocketGroup >= 5GGG` requires at least five linked sockets and at least three green sockets; `==` requires an exact count of the named colours. Invalid rules, test-drop colours and contradictory socket counts, colours or links show an explanation instead of a certain result. Spaces and other whitespace separate socket groups.

For strict `<` and `>` comparisons, a socket pattern matches when **any** specified count satisfies the comparison. For example, `SocketGroup < 4RG` matches a four-link with no red socket. This follows [GGG's explanation of socket matching](https://www.reddit.com/r/pathofexile/comments/f2t4tz/comment/g0xmhhp/?context=10).

If the supplied socket count and colour list disagree, colour-dependent socket checks report unknown. A count-only alternative can still match independently. Negative socket-colour and linked-group comparisons also report unknown until their game behaviour is verified; numeric-only negative `Sockets` comparisons are supported.

For modifier or enchantment counts, the game requires the operator and number together, such as `HasExplicitMod >=2 "of Haast" "of Ephij"`. The rule editor formats this automatically and flags a separated operator in imported rules.

**Import** accepts `.filter` and `.ruthlessfilter` text. The original text stays in the build, separate from personal rules. The compiler adapts GGG's announced 3.30 BaseType renames and removals and adds Show rules for new items. If removing old items empties a BaseType list, it discards that entire block instead of broadening it. **Audit / update** lists migrations and parser diagnostics. New items remain visible rather than receiving invented economy tiers.

For a filter with `Import` lines, open **Profile tools → Included filter files**. **Find unresolved** lists missing and circular references, including nested files. Select a missing name and paste its contents, or select a cycle to edit the included file. Choosing a name alone does not create an empty file. Switch to **Add a file** for another, then select **Keep files**. The build stores those copies; the compiler expands them in order for preview and export, including nested imports. Missing or cyclic references remain in the output. The preview is unknown if it reaches one; an earlier terminating match can still be shown, with a warning that later included files must be valid and available when required. Export reports also include grouped unresolved names and whether each is optional or circular. No files are read from the game folder.

**Full file changes** compares the kept profile with the working draft. Switch between compiled output and original base text, search changes or inspect complete before/after views. Copy preserves full source text; long lines are abbreviated only on screen. Large or repeated changes can be grouped rather than reduced to a minimal patch. Detailed review is bounded to 100,000 lines; available full sources can still be copied if that guard is reached.

**Keep in build** keeps all profiles; normal build **Save** persists them. Native XML, shared builds and complete planning bundles carry kept profiles. Working drafts survive planning-page navigation but must be kept before saving or sharing. There is no profile-count cap; a 2 MiB metadata guard protects build loading. Unreadable or future metadata is preserved unchanged.

**Export** copies compiled text or writes a UTF-8 `.filter` for Normal mode or `.ruthlessfilter` for Ruthless to your chosen directory. If imports remain unresolved, **Review imports** distinguishes required, optional and circular references. They remain in the exported text; attach the files or provide required files alongside the export. Existing files are preserved; choose another filename to export a replacement. **Save all seven strictnesses** writes `name-0.filter` through `name-6.filter`, or `.ruthlessfilter` variants in Ruthless, carrying personal rules and global appearance into each preset. It checks every destination before writing and cancels the batch if any file exists. **Save strictness ZIP** packages those same seven mode-specific files into one archive; extract it before selecting a filter in game. Imported filters have no strictness variants. Export does not install, activate or silently replace game files.

**Account filters** supports listing/importing filters and explicit publication with server validation. The **Log in** action requests `account:item_filter` in addition to normal PoB scopes. GGG must permit that scope for the registered OAuth client; ordinary character-import authentication is not sufficient. If permission is unavailable, use local export. A second review names the destination before creating a private filter or replacing a selected filter. No account changes occur through MCP. Pending processing, validation errors and uncertain write outcomes are reported without automatic retries. Live account sync has not been verified with a filter-authorised account.

## AI tools

`test_loot_filter_examples` evaluates a saved example set using a kept profile or a supplied draft. Results are paged: use `nextOffset` to continue through the set. Each result retains its example index and explains uncertain matches; long lists of matched rules are marked when truncated. Use `test_loot_filter` for a single example's complete style details. Evaluation yields between examples; compiling the filter and evaluating a single item can still pause briefly. The tool does not change or export the filter; poll the request status as with other AI planning tools.

`test_loot_filter_scene` evaluates the built-in simulator scenes in pages and returns each exact sample alongside its result. Supply a scene name, optional seed and area/item levels; use `nextOffset` for later pages. Build-target examples are generated from the current build without changing the filter. Their response includes up to 20 generation warnings and a total count; `generate_loot_filter` returns the complete warnings. These are deterministic examples rather than drop rates or live values.

On **Simulate**, **Paste item** reads visible properties from a game clipboard copy, including explicit fractured and synthesised item markers and influence markers on ordinary equipment. A line marked (implicit) establishes HasImplicitMod; without that marker the property remains unknown. When the item's base is identifiable and its class is missing, known unambiguous base names can supply the class; an explicitly copied class takes precedence. An incomplete identified rare or unique with no recognizable base stays unknown for base-type rules. Known non-Vaal transfigured gems receive their base skill when the bundled data identifies it unambiguously; unknown and Vaal variants remain unknown. Known non-equipment and fixed-defence bases also receive their filter defence percentile; random rolls and unique equipment remain unknown. Influence on unique items and maps remains unknown when it cannot be determined reliably. If equipment text has no socket line, socket counts and links remain unknown; enter them in the sample editor when available. Advanced copied descriptions can supply explicit modifier names as partial evidence: known matches can decide a rule, while missing names remain unknown. To provide a complete list, set **Identified** to Yes and enter quoted modifier names in **Has Explicit Mod**. Leave that field blank if the names are unknown, or enter `[]` for a known empty list. **Scene settings** controls shared area/item levels and background; **History** revisits tested samples. **Matched rules** opens the deciding blocks for inspection and editing. **More sound, icon and beam options** includes all twelve icon shapes, colours, sizes, positional/custom alerts and temporary beams. Native previews approximate their geometry; custom audio files must accompany the exported filter.

Catalogue examples use the bundled client data to infer an item class when the exact base name has one unambiguous class. Some names, including resonators, can represent multiple classes; those examples keep the class unknown unless the rule specifies it.

For current tier-based ordinary maps, pasted item names supply the map tier even when there is no separate tier line. Named quality lines such as `Quality (Pack Size)` also supply the quality value. Conflicting copied values are rejected; this has been tested with synthetic copies, not verified in game.

Modifier-count conditions with a separate `==` operator are preserved when edited, but their preview is uncertain until the combined syntax is verified in game.

- **get_loot_filters:** read kept profiles.
- **generate_loot_filter:** derive a separate draft from build plans.
- **test_loot_filter:** evaluate either a drop with exact filter property names (`sample`) or copied game item text (`itemText`). For copied items, optionally provide `areaLevel`; the response includes the interpreted sample so known and missing properties can be checked.
- **export_loot_filter:** return compiled text and diagnostics; never write files.
- **propose_loot_filters:** submit profiles for native desktop review. Read and preserve existing profiles before replacing them.

Generation, testing and compilation return request IDs. Poll **get_proposal_status** and match the ID. Only native **Apply** keeps a proposed change; normal **Save** persists it. The existing 256 KiB MCP request guard applies to imported templates as well; larger imports can use the native editor.

## Sources and updates

The seven bundled templates are [NeverSink's filter](https://github.com/NeverSinkDev/NeverSink-Filter), version 8.21.0e from the unreleased source commit `7c8f374b802564aa265a00061a0cd1d009afc0fb`. They are MIT-licensed; the copyright and permission notice is included in `src/Data/LootFilters/LICENSE-NeverSink.txt`. These 3.30-native presets keep NeverSink's own item tiers and rules. Existing bundled profiles require an explicit **Audit / update** before exporting with the new base. This is our native workspace, not the FilterBlade website or its hosted economy service.

GGG's [Covens of Umbra item-filter announcement](https://www.pathofexile.com/forum/view-thread/4013923) supplies the pinned 3.30 item additions, renames, removals and new keywords. [GGG's filter guide](https://www.pathofexile.com/item-filter/about) defines filter syntax; [the API reference](https://www.pathofexile.com/developer/docs/reference#itemfilters) documents account access and server validation.

Maintainers run `python tools/update_loot_filter_data.py --commit <immutable-commit>` to refresh templates and the announcement snapshot. Source URLs and SHA-256 hashes ship beside the data. Refreshes travel through fork releases; there is no live price feed or FilterBlade subscription. Profiles record their base revision and require an explicit **Audit / update** after the bundled template changes. Personal rules and original imported text are retained.
