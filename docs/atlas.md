# Atlas planner

For up to six new targets, the planner checks its exact route after the original-order comparison and skips further ordering when that route passes the budget checks. In a 20-run headless CPU benchmark on the bundled 3.30 tree, a six-target route took about 143 ms on average versus 161 ms before this change, with the same 36 added nodes. This is a bounded measurement, not a native desktop responsiveness test. Run `python tools/run_headless_lupa.py --filesystem tools/benchmark_atlas_route.lua` to repeat it; pass an older `AtlasPlanner.lua` path to compare another revision.

Open **Atlas** beside **AI builds**, or switch to **Atlas** in the full-width planning workspace. **< Build** returns to your previous build tab.

Under **Plan tools → Map modifier explorer**, choose a map base, rarity, tier and item level to inspect hypothetical modifiers on a graphical map card. Current tier-based maps use bundled game-generated item artwork, available offline. Search and add modifiers to see which groups remain available, or use the experimental currency picker to generate modifier identities and estimated values. The picker disables incompatible currencies and explains the modeled restriction. No real currency is spent. The tool does not create an in-game item, calculate verified probabilities, or establish current base availability.

**Plan tools → Thread restrictions** checks the seven area-level and Thread-count conditions published in [3.30.0b Hotfix 3](https://www.pathofexile.com/forum/view-thread/4015683). It also shows modifier guarantees when spending Threads and the published 3/6/8 Thread milestones from [3.30.0c](https://www.pathofexile.com/forum/view-thread/4017172). Enter the applied count for one Thread type, including free or bonus Threads, and the separate number spent. The spent count cannot exceed the applied count. Each listed type is checked with those inputs independently; whether spending other Thread types changes the restriction is unverified. Under that assumption, one spent Thread restricts the listed modifiers from the earlier patch. The similarly worded Abyss modifier added in [3.30.0d](https://www.pathofexile.com/forum/view-thread/4017726) may have different eligibility, so the planner leaves its current restriction unknown and shows the earlier rule separately. The same patch added an Incursion Architect room; it is listed as a possible addition, not a guaranteed offer. If spend is omitted or zero, single-spend eligibility remains unresolved. Free-only modifier guarantees are not established. AI results expose the conditional value as `guaranteedWhenSpending`; `guaranteedModifiers` is omitted when the spent count is zero or unknown, and `guaranteeStatus` explains the case. Milestone values are shown at the reached threshold without assuming how separate thresholds stack. For Abyss, the same spend input checks the 3.30.0c restriction that Abyssal Consorts cannot appear when only one Abyss Thread is spent. The helper does not infer eligibility for other counts. This is a current-game reference, including when viewing an older tree; it does not predict offers or odds. AI clients can check the same inputs with `check_thread_restrictions`.

From **Shaped Regions**, select a recorded map and choose **Check Threads** to start with that region's observed free count. Add any spent or bonus Threads of the same type and check the area level; the tracker does not know those values automatically.

1. Choose the exact tree version. We bundle official **3.27.0, 3.28.0j, 3.29.1 and 3.29.3** Standard and Ruthless graphs, the launch **3.30.0-preview** graphs, and **3.30.0c** graphs for both modes. New 3.30 plans and plans with an unrecognized character-tree version default to the bundled 3.30.0c graph in the character's mode; existing plans keep their original version. The fallback does not imply that a later game version has the same Atlas. The pinned 3.28.0j Standard and Mirage graphs match within each mode; earlier 3.28 patches may differ. The 3.30 trees have **150 base points**. Standard and Covens graphs match within each mode at each bundled revision, but Ruthless has different modifiers. Other historical league-specific Atlas variants are not included.

   The launch snapshots match GGG's [3.30.0 tag](https://github.com/grindinggear/atlastree-export/releases/tag/3.30.0). The 3.30.0c graphs and art use GGG's [3.30.0c export commit](https://github.com/grindinggear/atlastree-export/commit/24bd611b33fb727c0d1264185599fdd973d02d2d); all four source files and both generated graphs were checked. These checks do not independently verify the live game's tree. Run `python tools/check_atlas_release.py` to repeat the current comparison; use `--version 3.30.0-preview` for the launch snapshot.
2. Enter a name and the number of Atlas points you have earned. The initial budget is the tree's maximum; it does not read account progression. On older trees, you must have enough earned points to reach Unwavering Vision before its granted points can be used. The reachability check respects avoided nodes, including for temporary paths. Plans that cannot reach it are flagged; when a temporary path is needed, the planner attempts to construct a connected, budget-valid sequence. A found sequence and its refund count are available in **Allocated stats** and the AI report. In **Allocated stats**, select **Temporary grant route**, choose **Inspect route**, then select a step and **Show on tree** to locate that node. Use **Prev** and **Next** to move through the route, then **Exit route** to restore the normal tree controls; a route it cannot prove remains marked for review. Refunds consume currency, which is not priced automatically. Previously saved plans remain readable.
3. Filter a mechanic directly in the inspector, or search names and stat text. Matching nodes highlight and preview a result without moving the camera. Choose a result or press **Go** to center it. The inline list includes every match and can be scrolled; changing the search returns it to the first result. With the list focused, Home and End jump to its first and last entries, and Page Up and Page Down move by a page. Result labels update their added point costs after edits. Repeated names include an approximate tree location and node ID; select one to center it. Use **Connect +N** to add the previewed shortest connection.
4. Use the mouse wheel to zoom and drag empty space to pan. **Fit tree** resets the view. The canvas uses the official background, node icons, frames and mechanic emblems. Allocated paths are gold; avoided nodes have red frames. Hover for modifier descriptions. Double click a node to connect it, or remove it if allocated.
5. **Avoid selected** excludes a node from future paths. Desired and avoided preferences are saved with the plan and portable JSON. **Remove branch** also removes disconnected allocations. **Undo** and **Redo** restore allocations and preferences. Press Enter after editing a budget to include it in history.
6. Open **Notes & sharing** for farming notes and import/export. Choose **Keep plan** to keep the draft in this build. This changes unsaved metadata. Use the normal build **Save** to persist it. Saved plans have a total metadata size guard, with no eight-plan count limit. **Saved plans** opens or deletes saved plans and lists unkept session drafts. Choose **Discard draft** to remove a session draft and its current-session recovery copies; older recovery records remain available for review. Session drafts are not saved with the build until kept.

The 3.30 preview includes multiple-choice nodes. Connect one, select it, and choose **Choose effect**. The selected effect appears in the node details and allocated stats, and stays with the saved plan, undo history and versioned plan JSON. Unselected choice nodes are listed in **Allocated stats**. Search includes every available effect. Official links carry selected effects once every allocated choice node has one. Use **Copy plan** to preserve the exact tree version and planning notes as well.

Stage routes call out new or changed effects, including effects that must be reselected after a refund. For a retained node whose selected effect changes, the review flags that the in-game reselection procedure and its cost are unverified; those possible costs are not included in the node-refund count. AI review shows the chosen effect, and linked loot-filter suggestions use the selected effect rather than the alternatives. An effect that excludes a Thread type suppresses inferred pickups for that type; explicitly named strategy items remain visible.

In a strategy's **Avoid** field, a recognized mechanic name such as `Breach` suppresses that mechanic's Thread pickups from the same Atlas plan, including Threads named in its supplies. A separate budget or another plan can still request the item.

The allocation summary lists selected Thread exclusions and warns if another selected effect increases the same Thread type. A Thread exclusion applies to Threads found in your Maps; it does not prevent the corresponding encounter from appearing.

**Find nodes** opens a searchable list with mechanic filters and added point costs. Choosing a result highlights its mechanic on the tree. The minimap moves the camera without changing allocations. Drag the divider beside the inspector to resize it.

Mechanic filters include Mirage, Wildwood, Sentinels, Torment, Rogue Exiles, Mercenaries, Ore Deposits and Threads. A node that mentions multiple mechanics appears in each applicable filter; the investment summary assigns one primary category per node so its totals do not double-count points. Categories are based on node text and are not a simulation of encounter interactions. Linked loot-filter suggestions consider all applicable categories.
Automatic starting routes avoid allocating nodes that explicitly prevent encounters, unless already allocated. Search results and the selected-node details flag these blockers; forced encounters may behave differently. This routing precaution does not change saved avoidance preferences; blocking nodes remain available for manual plans. Review each suggested route and its keystones before applying it.
In 3.30, Harvest includes Sacred Flora and Fauna; the Wildwood filter focuses on the Viridian Wildwood encounter rather than every effect that mentions Wildwood Wisps.

**Targets** collects desired nodes; Shift-click marks them directly on the tree. Toggle a mechanic's notables together, then preview a route retaining existing allocations or rebuilding from the start. Recalculation runs in short background slices, with pause/cancel controls. Review added/refunded points, connected targets and keystone effects, then **Use preview**. Changed plans require recalculation. For up to six distinct targets that are not already allocated, the optimizer finds the fewest added nodes while retaining existing allocations and respecting exclusions, when that route passes the budget checks. Larger sets compare a bounded selection of target orders and sampled pair swaps. The preview labels them as heuristic: they can miss a shorter or budget-fitting route. The minimum-node result does not prove a refund sequence for granted points.

**Routes** compares the shortest connection with available alternatives. In **Plan tools**, mark a selected node as a preferred waypoint, open editable mechanic starting routes, compare the draft with a saved plan, or restore an earlier history state. Starting routes compare target orders and connect up to three reachable, unallocated nearby notables from the bundled graph; they do not predict farming income. Route comparisons honor the current budget and exclusions. In **Stages & strategy**, choose a previous stage and use **Copy route** to copy its refund and allocation steps with their point-budget assumptions. **Show on tree** previews the allocation after each route step, starting from the previous plan. **Exit route** returns to the stage editor with unfinished inputs intact. The preview does not change the destination plan or track in-game allocations. It keeps starting-reachability and choice-effect warnings visible.

For older trees with point-granting nodes, the stage comparison checks whether the starting allocation can be reached with the assumed earned points. An impossible legacy starting plan has no route offered; if reaching it may require a temporary path and refunds, the comparison says its starting state is unverified.

If an imported stage references a missing, incompatible or cyclic previous stage, **Stages & strategy** shows the unavailable link and keeps it in the draft. Choose another saved stage or **No previous plan** to resolve the link before saving the plan.

**Allocated stats** opens an investment overview, mechanic counts, keystone tradeoffs and searchable raw bonuses. Saved-plan comparison can overlay added paths in green and removed paths in red. Counts are not effective map odds: increased effect, conditions and keystone interactions are not simulated. Atlas allocations do not change character DPS or EHP.

## Sharing

In **Saved Atlas plans**, **Undo removal** restores the most recently deleted saved plan during the current build session, including its Genesis allocations. It will not replace another plan with the same ID, and a missing or incompatible previous stage must be repaired first. Save the build to persist the restoration.

**Copy plan** exports JSON with the exact patch version, point budget, allocations and notes. **Paste plan** imports that JSON into the current draft. Review it before keeping it.

In **Targets**, calculate a route and choose **Show on tree** to review its additions in teal and refunds in red. Avoided nodes are also red. The draft stays unchanged. Open **Targets** again to apply the preview or return to the current tree; editing the plan clears the overlay.

**Official link** copies a version-six `pathofexile.com/fullscreen-atlas-skill-tree/` URL. These URLs do not contain a patch version. For an official URL import, first select its original patch and budget, then use **Paste plan**. The importer rejects unknown, disconnected and over-budget nodes. Node IDs can survive between patches while changing meaning, so a successful import is not proof that the selected patch is correct. Use our JSON format for reliable versioned sharing.

Other planners' proprietary links, old URL formats and shortened links are not imported. Export an official Atlas URL from that planner first. The official website may display a different patch from an older saved plan.

## AI tools

Reconnect the MCP client after updating. Enable build proposals in **AI builds**.

- `get_atlas_plans`: read saved plans, bundled versions and the build revision.
- `search_atlas_nodes`: search a selected official graph for native node IDs and text.
- `compare_atlas_plans`: compare two plans on the same tree and review a budget-aware refund and allocation route, including starting-plan reachability warnings and additive modifier changes before interactions. These changes are not effective map chances. Saved Genesis allocation differences are listed separately; Atlas route steps do not include Genesis, whose point and refund rules remain unverified. A missing Genesis section does not establish in-game allocations. It does not change either plan.
- `plan_atlas_tree`: connect up to thirty desired IDs to a plan, optionally avoiding nodes. Returns a separate draft, added nodes, point accounting, stat text and an official link where supported. Plans may include `choices` entries with the allocated `node` ID and selected `effect` ID from search results.
- `propose_atlas_plan`: submit that plan for normal desktop review. Only the desktop **Apply** button commits the candidate; build **Save** persists it. Its review identifies changed allocations, choices, strategy fields, Genesis and saved map drafts.

Search and routing are queued. Poll `get_proposal_status` and match the returned request ID. Neither tool applies changes. Routing uses deterministic shortest connections in target order. Set `optimize: true` to compare target orders and, for up to six distinct unallocated targets, find the minimum added-node route when it passes the budget checks. Larger sets use a bounded heuristic with sampled pair swaps. Starting-route suggestions use the faster order comparison. Existing allocations and exclusions stay intact; the final tree must fit the supplied budget. The response reports whether the result is heuristic, the number of orders checked and savings against the original order when that order was valid. Ruthless results include an official Ruthless URL when every allocated choice node has an effect selected. Gateways use the official graph links. Granted Atlas points are counted in the final budget; a minimum-node route does not itself prove a refund sequence to reach a grant.

Example request: “Use my Atlas version and a 90-point budget. Find Essence and map-sustain nodes, avoid mechanics I dislike, and propose a connected farming plan. Explain the keystones and tradeoffs before I apply it.”

The planner does not fetch character Atlas completion, scrape community trees, provide popularity heatmaps, price supplies or predict farming income. **Stages & strategy** records progression, respec routes, maps, supplies, requirements and dated setup estimates. Previous-stage choices exclude plans that would create a progression loop; see [connected planning tools](planning-workflows.md).

## Sources and maintenance

Node names, stats, links, positions, point limits, granted points and artwork come from [GGG's official Atlas export](https://github.com/grindinggear/atlastree-export). Each bundled graph records its immutable source URL, commit and SHA-256. Decorative mastery icons are excluded from allocation. Artwork is bundled from the same pinned official export; planning works offline. No third-party planner code or artwork is bundled.

The preview uses exported spawn weights and assumes uniform suffix selection; weights and game interactions are unverified. Nightmare versions of those modifiers use the same experimental candidate model. If the selected removal has no supported replacement, the preview stops without changing the map; the picker warns when that can happen. The action is also available through `simulate_map_currency` for AI tools. Drafts saved against 3.30.0.2.2 or 3.30.0.3 can be opened and reviewed with current data; the saved version changes only when the draft is kept again. Other saved data versions still require review.

In **Map modifier explorer**, **Use currency** can generate hypothetical modifier identities and stat values for Transmutation, Alchemy, Alteration, Chaos, Augmentation, Regal, Exalted, Annulment and Scouring. `simulate_map_currency` exposes the same seeded model through MCP. Base searches, copied-map reviews, currency simulations and reroll results identify the data version and source used. The model assumes an equal chance of one or two magic modifiers and the equipment simulator's 8:3:1 distribution for four, five or six rare modifiers; it selects eligible modifiers by spawn weight, removes uniformly, and samples varying stats independently and uniformly. These assumptions, map-specific interactions and outcome probabilities are not verified. Values are displayed only when PoB's range description matches the pinned source text; unmatched and manually added modifiers remain ranges. For an ordinary rare map, **Vaal: +2 modifier outcome (conditional)** previews the 3.30 corruption outcome that adds two modifiers. It preserves existing rolls, marks the result corrupted and clears reroll settings that no longer apply. Saved drafts retain a conditional-preview marker, including when shared with AI tools; manual changes can alter the draft afterward. For ordinary maps of any rarity, **Vaal: corruption implicit** samples one eligible implicit from the pinned 3.30.0.2 weights, and **Vaal: no other change** preserves the map apart from corruption. For ordinary rare maps, **Vaal: reroll at same tier** samples the reroll outcome without changing the base or tier. These are selected conditional outcomes, not full Vaal Orb rolls; overall outcome probabilities, weighted selection, uniform implicit values, side limits and interactions are unverified. The implicit model applies the pinned item-level and Blighted restrictions. Nightmare corruption, other Nightmare-map currency actions, other special maps and other currencies remain unsupported.

For a magic or rare map, select wanted modifiers on the card and choose **Estimate rerolls**. Add any modifiers to avoid, then set the number of trials and maximum rolls per trial. Options and exclusions match exact modifier IDs, so related tiers must be added explicitly. The estimator rejects target combinations it can prove conflict under the modeled modifier groups and prefix/suffix limits; change a target or add a compatible option. Its compatibility search is bounded, so other impossible combinations may not be detected. Vaal outcome probabilities are not modeled. Up to 20,000 rolls may be requested across all trials, and the background job can be cancelled.

## Shaped Regions

In a 3.30 Atlas plan, open **Plan tools → Shaped Regions** to record the maps and free Threads you observe for each Thread type. Select a map and choose **Record map run**, or choose **All recorded maps** to compare overlaps across regions and record a run from there. Then check the region objectives you completed. The map is removed from every recorded region containing it; each checked region adds one free Thread to its other recorded maps. Leave an objective unchecked if it was not completed.

These are manual observations, not a game or account import. Unlisted maps, Thread limits and other in-game restrictions are not predicted. Keep the tracker in the Atlas draft, keep the Atlas plan and save the build to persist it. Plan JSON and AI Atlas proposals also carry these observations. Changing Atlas versions starts a separate empty draft.

AI clients can call `preview_shaped_region_run` with an Atlas plan, map name and explicitly completed region objectives. It returns a separate proposed plan and the remaining recorded maps; it does not access the game or save the build. Use `propose_atlas_plan`, review in PoB, then save to keep the result.

Divine Vessel can be added as a conditional Deified plan in the map currency browser and MCP. The plan is stored separately from copied effects and can be removed without changing them. The documented boss bonuses are a reference, not map-wide rarity; item eligibility, other enchantments, corruption order and Pantheon capture need in-game verification.

The map editor and MCP can plan one Allflame scenario using 11 currency descriptions and artwork from the pinned 3.30.0.4 client export. Plans are separate from copied map effects. MCP map inspection lists hypothetical planning options separately from currency availability, including for corrupted or mirrored maps. Eligibility, multiple-ember behavior, replacement, other enchantments, corruption order, and actual packs and drops require game verification. Rebuild the catalogue with `python tools/update_map_allflame.py --base-items path/to/base_items.json` and verify it with `--check`.

A corrupted generic rare map can also preview **Temple: +2 modifiers (hypothetical)** in the currency picker or through `simulate_map_currency`. The [3.30 patch notes](https://www.pathofexile.com/forum/view-thread/4013680) introduce a Temple device for a second map corruption, but do not establish this particular outcome or implicit retention. The preview assumes both, marks the map twice corrupted, and does not estimate outcome odds. Saved drafts and MCP inspection retain the Temple preview warning. Special effects and other bases are excluded.
